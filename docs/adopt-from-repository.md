# Adopt this workflow

Use a fork, repository template or clone of [AI-Agent-Job-Applications](https://github.com/Aniekanetim/AI-Agent-Job-Applications). A URL gives an agent instructions to read; it does not create a local working copy, authenticate accounts or activate a schedule.

Read README, AGENTS and SETUP at a consistent revision. Record that workflow revision separately from candidate-profile/CV versions and website observations. Preserve existing destination files and instructions when merging; do not overwrite another project's working contract or source data. Read the nested working contract explicitly if the destination agent does not automatically discover it.

Create a private operational copy. Complete self-contained role profiles and enable actual roles in routing. Use local counterparts for private values, documents and accounts. Keep the public upstream package unconfigured. Do not copy another candidate's CV, account session, application evidence or schedule.

The agent receives assignments through the configured job-alert inbox and user To Do tickets. It follows the application and discovery procedures autonomously, with no QA approval gates. Concrete missing dependencies move to Blocked. Confirmed submissions move to Applied. Existing authorization covers routine work; missing facts must not be invented.

The initial architecture maps/routines have no learned selectors or verified host flows. A browser-capable agent discovers those from actual access, then maintains them. The optional TypeScript tools validate state/helper behavior; they are not an LLM, scheduler or universal site adapter.

For a new machine, follow [portability](portability.md). A repository-reading agent without browser or inbox access cannot complete those dimensions until its tools are connected. Report the specific missing capability rather than claiming success.
