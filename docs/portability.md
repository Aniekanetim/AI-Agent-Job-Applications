# Reuse and move machines

## Another candidate or independent setup

Start from a fresh fork/template/clone with empty live queues and no copied outcomes. Supply that candidate's own role profiles, routing, CVs, platform accounts and inbox. The QA source project and an existing job-application copy remain independent. Do not inherit another person's authority, facts, submissions or schedule.

## The same candidate on another machine

The public clone alone lacks ignored working data. Transfer the selected role's actual *.local.md files and documents, live board tickets, private shared progress, .local/inbox-state.json and necessary restricted evidence through an appropriate private mechanism. Preserve IDs, source-message/vacancy associations, chosen profile/CV versions, questions, confirmations, cleanup state and checkpoints. Transfer learned site maps/code with their real observation versions, excluding embedded personal data.

Reconnect authentication securely. Credentials, cookies and session files are not product knowledge and should not be published or treated as portable login instructions. Reestablish platform and inbox access on the destination.

Recheck actual paths, CV hashes, tools, relevant page conditions and worker ownership. Read the exact task's Submission attempted checkpoint before any retry. Confirm an uncertain result on the portal, rather than starting another application. Retry outstanding cleanup using the same message reference without resubmitting.

If an old scheduler still runs, coordinate its claim/ownership before launching another worker. File transfer neither moves nor disables it. Configure a new schedule only when requested with its actual root, cadence and timezone.

## Maintain the reusable package

Keep public templates blank, boards empty and example routines marked unlearned. Publish workflow improvements and sanitized generic code deliberately; do not push active candidate records. Updated public instructions do not silently rewrite ongoing task history or claimed site evidence. Record the adopted version and resume from the actual checkpoint.
